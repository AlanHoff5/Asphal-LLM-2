Tokenization / Tokenizer — Tokenização / Tokenizador: Processo (e o componente que o executa) de dividir um texto bruto em unidades menores, os Tokens, antes de qualquer outra etapa do pipeline. É o primeiro passo entre o texto e o modelo, e sua saída alimenta diretamente a construção do Vocabulary. Existem diferentes estratégias, da mais simples baseada em regras (dividir por espaços e pontuação) até o Byte Pair Encoding usado pelo GPT. A frase "Hello, world." vira os tokens ["Hello", ",", "world", "."].

Token — sem tradução consagrada, mantém-se o termo em inglês: Unidade mínima de texto produzida pela Tokenization — uma palavra, parte de uma palavra ou um sinal de pontuação. É sobre essa granularidade que o restante do pipeline opera: cada Token vira um Token ID, que por sua vez vira um Embedding. No texto de exemplo do capítulo ("the-verdict.txt", 20.479 caracteres), a tokenização baseada em palavras produziu 4.690 tokens.

Vocabulary — Vocabulário: Conjunto fechado de todos os tokens únicos conhecidos pelo modelo, organizado como um dicionário que mapeia cada token a um Token ID (e vice-versa). Define o "alfabeto" que o Tokenizer pode produzir; qualquer palavra fora dele precisa ser tratada por um Special Context Token ou decomposta via Byte Pair Encoding. No experimento com tokenização por palavras, o vocabulário construído a partir de "the-verdict.txt" ficou com 1.132 entradas (1.130 tokens únicos mais dois tokens especiais).

Token ID — sem tradução consagrada: Identificador numérico inteiro atribuído a um Token dentro do Vocabulary. É a forma que o texto assume para ser manipulado computacionalmente — o modelo nunca vê a palavra "gato", apenas o número correspondente a ela. Antes de virar Embedding, uma sequência de texto é primeiro convertida numa sequência de Token IDs; a relação Token ↔ Token ID ↔ Vocabulary é o núcleo desta etapa. Exemplo: com o tokenizador BPE do GPT-2, a palavra "Hello" corresponde ao Token ID 15496.

Special Context Tokens — Tokens Especiais de Contexto: Tokens artificiais adicionados ao Vocabulary para marcar situações que a tokenização comum não cobre, como palavras desconhecidas (`<|unk|>`) ou a fronteira entre dois documentos concatenados (`<|endoftext|>`). Permitem que o Tokenizer lide com texto fora do vocabulário sem quebrar, e o `<|endoftext|>` em particular sinaliza ao modelo onde um trecho de treino termina e outro começa. Ex.: ao juntar dois textos diferentes, insere-se `<|endoftext|>` entre eles antes de tokenizar.

Byte Pair Encoding (BPE) — sem tradução consagrada: Algoritmo de tokenização por sub-palavras usado pelo GPT-2 e GPT-3 (via a biblioteca `tiktoken`), que constrói o vocabulário mesclando repetidamente os pares de caracteres mais frequentes. Sua vantagem sobre a tokenização por palavras é nunca precisar de `<|unk|>`: qualquer palavra, mesmo inventada, pode ser quebrada em sub-unidades já conhecidas. Usa um vocabulário bem maior (50.257 tokens no GPT-2) e tende a gerar mais tokens por trecho de texto do que um tokenizador simples baseado em palavras — no experimento do capítulo, a mesma frase gerou 21 tokens com o tokenizador por palavras e 31 com o BPE, já que este quebra algumas palavras (como "Palacio" ou nomes fora do inglês) em pedaços menores.

Input-Target Pair — Par Entrada-Alvo: Par formado por uma sequência de Token IDs (entrada) e a mesma sequência deslocada em uma posição (alvo), usado para treinar o modelo na tarefa de Next-Word Prediction. Cada posição da entrada tem como alvo o próximo Token ID da sequência original. Com Context Size igual a 4 sobre a sequência `[40, 367, 2885, 1464, 1807]`, a entrada é `[40, 367, 2885, 1464]` e o alvo é `[367, 2885, 1464, 1807]`.

Sliding Window — Janela Deslizante: Técnica usada para percorrer a sequência de Token IDs e extrair múltiplos Input-Target Pairs, avançando um número fixo de posições (o Stride) a cada passo. É o mecanismo por trás do `GPTDatasetV1`, responsável por transformar um texto inteiro em várias amostras de treinamento sobrepostas ou não. Um Stride igual ao Context Size produz janelas sem sobreposição; um Stride menor produz mais amostras, mas com conteúdo repetido entre elas.

Context Size / Context Length — Tamanho de Contexto: Quantidade de Tokens que o modelo enxerga de uma vez em cada amostra de entrada. Determina o tamanho da Sliding Window e, junto com o Stride, define quantas amostras um texto produz — quanto maior o contexto, menos amostras cabem no mesmo corpus. No experimento, o mesmo texto (5.145 tokens BPE) gerou 2.572 amostras com contexto 2, mas apenas 160 amostras com contexto 32.

Stride — Passo: Número de posições que a Sliding Window avança a cada nova amostra extraída da sequência de Token IDs. Controla a sobreposição entre amostras consecutivas: Stride igual ao Context Size elimina sobreposição, enquanto um Stride menor gera mais amostras às custas de conteúdo repetido, afetando diretamente o tamanho do Dataset resultante.

Embedding Layer — Camada de Embedding: Camada do PyTorch (`torch.nn.Embedding`) que funciona como uma tabela de consulta, convertendo cada Token ID em um vetor denso de dimensão fixa (`output_dim`). É treinável: seus valores começam aleatórios e são ajustados durante o treinamento para capturar relações semânticas entre tokens. O número de parâmetros da tabela é `vocab_size × output_dim` — com o vocabulário BPE (50.257 tokens) e `output_dim=256`, a camada de Token Embedding sozinha tem 12.865.792 parâmetros.

Token Embedding — Vetor de Representação do Token: Vetor denso produzido pela Embedding Layer a partir de um Token ID, substituindo o identificador inteiro discreto por uma representação contínua que a rede pode processar e aprender a relacionar semanticamente. É a mesma ideia de Embedding apresentada no Capítulo 1, aplicada concretamente ao pipeline de dados. Um lote de entrada de shape `(8, 4)` (8 sequências de 4 Token IDs) vira, após a Token Embedding com `output_dim=256`, um tensor de shape `(8, 4, 256)`.

Positional Embedding — Vetor de Representação de Posição: Vetor denso, também produzido por uma Embedding Layer, que codifica a posição de um token dentro da sequência (0, 1, 2, ...) em vez do seu conteúdo. É necessário porque o mecanismo de Attention da Sprint seguinte não tem noção intrínseca de ordem — sem a Positional Embedding, trocar a posição de dois tokens não mudaria o resultado do modelo. Somado ao Token Embedding, forma o Input Embedding. Neste projeto usamos a variante absoluta (uma posição fixa 0..context_size-1), a mesma abordagem do GPT original.

Input Embedding — Vetor de Entrada do Modelo: Resultado da soma entre o Token Embedding e o Positional Embedding, combinando "o que é o token" com "onde ele está" na sequência. É a representação final que efetivamente entra na primeira camada do Transformer (o mecanismo de Attention da Sprint 3). Mantém a mesma shape do Token Embedding, por exemplo `(8, 4, 256)` para um lote de 8 sequências de contexto 4 com `output_dim=256`.

Dataset — sem tradução consagrada: Classe do PyTorch (`torch.utils.data.Dataset`) que organiza os Input-Target Pairs extraídos via Sliding Window, definindo como acessar uma amostra individual (`__getitem__`) e quantas amostras existem no total (`__len__`). No projeto, `GPTDatasetV1` implementa essa interface para o texto tokenizado com Byte Pair Encoding.

DataLoader — sem tradução consagrada: Componente do PyTorch (`torch.utils.data.DataLoader`) que consome um Dataset e o organiza em lotes (Batch) prontos para o treinamento, cuidando de embaralhamento, tamanho de lote e descarte do último lote incompleto. É a ponte entre o texto pré-processado (Input Embedding) e o loop de treinamento do modelo, que nas próximas Sprints vai consumir esses lotes diretamente.

Batch / Batch Size — Lote / Tamanho de Lote: Conjunto de várias amostras (Input-Target Pairs) processadas juntas em uma única passagem pelo modelo, e o tamanho desse conjunto. Definido pelo DataLoader, o Batch Size afeta apenas a primeira dimensão dos tensores produzidos pelo pipeline — por exemplo, `batch_size=8` e `context_size=4` geram lotes de shape `(8, 4)` em Token IDs, sem alterar o Context Size nem a dimensão do Embedding.
